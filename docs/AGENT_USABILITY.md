# Agent 好用程度（两人低频版）

> 结论：现在逻辑对两人用够了，不用大改。最值得改的只有 2 行提示词 + 1 行显示，剩下的靠“固定说法”就行。

> **状态（2026-10-11 更新）：** §2 的 5 个坑里，**第 4（头围写进去查不出来）与第 5（失败看不懂）已修复**；第 1 的“斤”与第 3 的“同日重复”已按 §3 补了提示词（无历史、无服务端换算、无日期级去重，所以第 2、3 只降低概率，未消除）。§5「不用做」的结论不变。
>
> 重要限制：**“斤→kg”仍只靠提示词，服务端不做换算**。所以“12 斤被写成 12kg”这类静默错误的风险只是降低、**没有消除**；服务端仍只卡 0.1–100kg 的宽范围。要真正消除需改契约（显式单位参数）或服务端合理性拦截，本轮未做。

## 1. 现状（已读代码）

- 每条微信独立规划，无聊天历史，最多 3 个工具（`weixin/src/agent.ts`）。
- 日期靠模型把“今天/昨天”按接收时间+Asia/Shanghai 转成 YYYY-MM-DD（`shared/agent.ts:calendarDate`）。
- 单位靠提示词转 kg/cm，服务端只卡范围：体重 0.1–100、身高 10–250、头围 10–100。
- 幂等只防同一条消息重试（messageId+op_key），**不防“同一天发两遍”**。
- 查记录回复只拼了体重+身高，**漏了头围**（`tools.ts:formatResults`）。
- 失败统一回“本次处理未全部完成，请检查权限、配置或重新说明需求”（`session.ts:267`），家人看不懂。

## 2. 两人用的坑（按中招概率排）

1. **“12斤”会被记错**：提示词没写斤→kg，模型可能按 12kg 写。家长最常用斤，这是最大坑。
2. **“刚才那个改一下”没用**：无历史，追问必须重发完整一句。
3. **两人重复记**：你发一遍、老婆又发一遍，同一天会落两条，没有日期级去重。
4. **头围查不到**：写进去了，查出来不显示，会以为没存上。
5. **失败看不懂**：技术话术，家人不知道是没说明白还是系统坏了。

## 3. 最小改动（建议主会话顺手做）

> 执行状态（2026-10-11）：第 3 条（头围）与第 4 条（失败话术）**已实现并有测试**；第 1、2 条提示词**已加入**；第 5 条软门限提示词**已加入**（服务端上限仍为 100kg/250cm）。

- `agent.ts` system 里加一行：`体重“斤”按1斤=0.5kg换算；只写数字没单位先追问，不猜。`
- `agent.ts` system 里加一行：`新增前若日期已有记录嫌疑，先用 list_growth_records 查当天，重复先问。`
- `tools.ts:formatResults` 的 list 分支把头围拼上（跟 create 分支一致）。
- `session.ts:267` 失败话术换成：`没记上，你按“日期+体重/身高”重发一句就行，比如：今天 体重6.5kg 身高70cm`。
- 软门限只写提示词不写代码：`体重>20kg或身高>120cm先确认，不直接写`（服务端 100kg 上限保留）。

## 4. 给家人的固定说法（贴微信群公告）

```
记一条：今天 体重6.5kg 身高70cm
记里程碑：今天 会叫妈妈了
查：查最近10条 / 查10月记录
改错：重发完整一句，不要说“刚才那个”
```

- 一句话只记一次测量，别把体重身高拆两条发。
- 没单位、说“斤”都可以，Agent 会问一句，答了再记。
- 同一天两条很可能是重复，去网页相册/成长页删一条就行，不用修 Agent。

## 5. 不用做的

- 不做聊天历史、不做跨消息改错、不做日期级唯一约束——低频人工看一眼比代码便宜。
- 不放宽 3 工具上限、不加新工具（照片/语音先不接）。
- 费用：单条一次 OpenRouter 请求+2048 token 上限，两人用基本忽略，失败重试最多 Queue 5 次，注意别在群里刷屏测试。
